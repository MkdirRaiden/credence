## Overview

This document summarizes the Prisma schema definition and database-level constraints for the Credence backend.

## Prisma Schema Merging

The Prisma schema files are modularized into `base.prisma`, `enums/*.prisma`, and `models/*.prisma`.

A custom CLI script `merge-generate.sh` is used to merge these schema files as part of the build and migration process. This script:

- Concatenates individual schema files into a single `schema.prisma` file.
- Formats and validates the merged schema.
- Runs Prisma client generation to keep client code in sync.

This merging approach follows best practices for modular and maintainable Prisma schema management.

## Database-Level Constraints

To supplement Prisma schema validation, additional SQL-level constraints are manually applied via migrations to enforce critical business rules and security policies directly in the database:

- User constraints (e.g., prevent self-referral, password hash must be NULL for external providers).
- OTP constraints (e.g., attempt limits, partial indexes for efficient queries).
- Referral code and redemption constraints (e.g., enforce time windows, redemption statuses consistency).
- Credit Ledger constraints (e.g., credit amount sign validation, source ledger integrity).
- Idempotency record constraints (e.g., state transitions with timestamps, response hash validation).
- Other indexes for performance optimization (e.g., refresh token expiry).

These manual constraints ensure robust data integrity even outside the application layer.
